# Changelog

All notable changes to this project are documented here. Versions are the
git tags (calendar versioning, `YYYY.MM.DD`).

## Unreleased

- `wv_footprint_from_imagettes`: build the time-ordered WV footprint from
  per-imagette geometries (OData `Imagettes`, STAC imagette items), e.g. when
  the product footprint was re-ordered by a GIS union; checked on 15,239 SOBA
  matchup items (imagette index and subswath recovered for every point inside).
- Zenodo DOI (concept, all versions): 10.5281/zenodo.24395550.
- Docs: new *How it works* page (methodology: inputs, models, calibration,
  accuracy, limits, in plain English); validation page rebuilt (examples
  for IW / EW / WV, WV on S1A / S1C / S1D, IW / EW accuracy vs latitude on a
  2026 sample); every figure regenerated by `scripts/make_figures.py`, in
  light and dark versions, with the statistics tables generated in the same
  run; stale WV figures (first look-angle law) and the duplicate *figures*
  page removed.
- Docs aligned with the code: Sentinel-1 is right-looking (the usage page
  said left-looking), WV is made of imagettes (not bursts), the IW / EW
  satellite distance from the footprint is a footprint-equivalent value
  (within ~9 km of the true one), CLI `wv` and `--beam` documented.

## 2026.11.20

Zenodo DOI of this version: 10.5281/zenodo.24395551.

### Added
- `s1_geometry.orbit.satellite_radius_km(lat, orbit_direction)`: the satellite
  geocentric distance from metadata only (fitted on POEORB state vectors of
  S1A / S1C / S1D, 0.10 km std), and `scripts/calibrate_orbit_radius.py`.
- WV angles from the CDSE OData metadata only: `estimate_wv_angles(..., r_s_km=None)`
  uses the orbit model; per-ring pass direction (products crossing the polar
  turn); optional sliding-window track fit for long products (`window=`);
  `on_outside="raise" | "nan"`.
- `estimate_geometry(..., mode="WV")` and the `s1-geometry wv` CLI subcommand.
- `s1_geometry.table.add_wv_angle_columns`: add the WV angle columns to a
  pandas table of reference points.
- WV validation on 164 Sentinel-1A / -1C / -1D L2 OCN products from the
  metadata only (`scripts/validate_wv_ocn.py`): RMSE 0.036 / 0.041 / 0.10 deg
  (incidence / elevation / heading); WV heading uncertainty 0.4 deg.
- `window="auto"` (default) in `estimate_wv_angles`: sliding-window track fit
  for products of more than 40 imagettes (halves their error).
- `merge_antimeridian_splits`: imagettes cut in two at +/-180 deg by the OData
  `Footprint` are re-joined.
- WV rings must be in time order; a re-ordered geometry (e.g. the `geometry`
  column of the daily Parquets) is rejected.
- `parse_wkt`: WKT / EWKT (`geography'SRID=4326;MULTIPOLYGON (...)'`, the OData
  `Footprint`) accepted wherever a polygon is.

### Fixed
- WV: the accepted satellite-distance band was the WGS84 *altitude* band
  added to 6371 km (7068.6-7096.8 km) whereas the real geocentric distance is
  7065.3-7082.4 km: 22 % of the orbit (half of |lat| > 50 deg) was rejected.
- WV: target points outside the footprint are rejected (25 % margin on the
  imagette radius: the ESA owi grid slightly overflows some rings) (they silently gave
  meaningless angles, e.g. 95.8 deg incidence).
- `orbit_direction_from_ring` (and `sar_ground_heading`) raise on rings too
  small to be a swath footprint (a WV imagette was classified `turning`,
  heading 270 deg).
- A MultiPolygon passed to the polygon functions now points to the WV API.
- CLI: long inline polygons crashed with "File name too long".
- Docs: the elevation is the radar elevation angle (off-nadir, ESA OCN
  convention), not `90 - incidence`; WV is the Wave mode, not "wide swath".
- Single source of truth for the version (git tag via `hatch-vcs`; the
  package said 0.3.0, the wheel 0.2.0).

### Changed
- WV look-angle law: the latitude term is a degree-5 polynomial evaluated at
  each imagette's latitude, refitted on 62588 S1C / S1D imagettes
  (`scripts/calibrate_wv_look_angle.py`); removes the northern-hemisphere
  incidence bias of the first law (up to +0.9 deg at 45-50 N): incidence RMSE
  0.233 -> 0.036 deg.
- WV per-point computation is vectorised.
- CI: Python 3.11-3.13 matrix, coverage, examples run, concurrency;
  Dependabot; ruff rules `I, UP, B, SIM, NPY`.
